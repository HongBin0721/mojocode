---
title: 目标模式
description: 给一个完成条件,每轮结束自动检查,没达成就接着干。
---

`/goal <条件>` 给出一个完成条件,条件原文即刻作为第一轮的指令发出。此后**每一轮结束**都由一次独立的模型调用判断条件达成没有:达成就收工,没达成就把判定理由当作下一轮的指令接着干,直到达成或触到刹车。

```
/goal 让 npm test 全部通过,且不改动任何测试文件
/goal                # 看状态:条件、轮数、已用时、token、最近一次判词
/goal clear          # 取消(stop / off / reset / none / cancel 同义)
```

条件写得越可验证越好:判定器只能读对话记录,不能自己跑命令,所以「`npm test` 退出码为 0」这种能在记录里看见输出的条件,远比「代码质量变好」可靠。它也被明确要求:记录里没有出现证据就一律判未达成,模型嘴上说的「应该能过」不算数。

## 刹车

三道,任何一道触发都会解除目标,而不是留着等你下次发言时又自己跑起来:

- `goalMaxTurns`(默认 10 轮)。无人看管的循环必须有上限,想跑长任务就调高,上限 100。
- `esc` 中断,或那一轮以错误收尾。不对着一个被掐掉或 401 的会话反复重试。
- 判定器连续两次给不出能读懂的判词。评估器坏了和确实没做完不能混为一谈。

## 循环期间

整个链条期间会话都算「忙」,输入框上方的状态行显示「目标 3/10 · 12s」。这时候发消息不会打断循环,而是作为下一轮的引导随判定器的指令一起喂给模型,随时可以纠偏。`esc` 停的是整个循环。

## 持久化

未完成的目标随会话存盘(扩展的 custom 记录),`/fork` 一起带走。`mojocode -c` 恢复回来时它是「已设定但不自动开跑」:状态行显示「目标待续」,轮数、计时和 token 基线全部重置,发条消息才接着往下做。打开一个旧会话不该凭空烧掉一轮。

| 键 | 默认 | 说明 |
|---|---|---|
| `goalModel` | 会话当前模型 | 判定用的模型 id,走当前服务商。判定只读一段抄本、只回两行,换个便宜的小模型能把附加成本压到接近零;`MOJOCODE_GOAL_MODEL` 可覆盖 |
| `goalMaxTurns` | `10` | 最多自动续跑多少轮,上限 100 |

`/goal` 是一个扩展(`src/extensions/goal/`),也是钩子层的验收:`turn_end` 里评估、`followUp` 续跑、`agent_end` 的 `aborted` 接住两轮之间的中断。
