---
title: 子任务
description: task 工具把独立子任务委托给子 agent。
---

主 agent 可以用内置的 `task` 工具把一个独立子任务委托给**子 agent**:它在全新的上下文里跑同一套循环,拥有同样的工具(去掉 `task` 自身与 `todo`,递归只放一层,会话状态归主 agent 管),最终只把一份报告带回主对话。价值在于上下文隔离:「把这 40 个文件翻一遍、总结调用关系」这类调研的中间过程不再挤占主上下文,主对话只收到结论。

不需要任何配置,模型自己决定何时委托。两种类型:

| 类型 | 工具 | 适合 |
|---|---|---|
| `general` | 与主 agent 同一套(去 task / todo) | 需要动手的独立子任务 |
| `explore` | 只读:read / glob / grep / web_fetch / web_search;MCP 工具不给 | 纯调研,更安全 |

运行中过程实时可见:工具行贴步数,下方缩进滚动显示子 agent 最近三条工具调用。轨迹只画在动态区,任务收尾即消失,时间线里只留一行摘要(`12 步 · 45.2k tokens`)。

```
⚒ Task(找调用点 · explore) · 5 步
   ⎿ Grep(handleSubmit · src/**)
   ⎿ Read(src/ui/App.tsx)
```

子 agent 的 token 消耗计入 `/cost` 与状态栏总量。子任务的完整过程(每一步消息)随会话落盘为 `task` 记录,事后排查「那个子任务为什么给了错结论」时有据可查。撞上步数上限或中途出错时,报告被显式标记为不完整,不会把半截调研当定论。`esc` 中断主轮时子 agent 立即跟着停。

| 键 | 默认 | 说明 |
|---|---|---|
| `taskModel` | 会话当前模型 | 子 agent 用的模型 id,与会话同一服务商。调研型子任务换个便宜的模型很划算;`MOJOCODE_TASK_MODEL` 可覆盖 |
| `taskMaxSteps` | `50` | 单次任务的步数上限,独立于主轮「默认无上限」;显式设了 `maxSteps` 则沿用它 |

钩子层对子 agent 同样生效,每个钩子输入带 `subagent: true`,拦截扩展按需区别对待。技能的 `context: fork` 走的也是这条通道。
