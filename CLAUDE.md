# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`mojocode` — a terminal coding agent (full-screen OpenTUI TUI + headless `-p` mode) that works with any LLM via the Vercel AI SDK (Kimi / DeepSeek / GLM presets + any OpenAI-compatible endpoint). ESM-only, TypeScript with `strict` and `noUncheckedIndexedAccess`. Runtime split: `-p`/subcommands run on Node ≥ 22; the TUI needs native FFI — Bun (primary, single-binary distribution) or Node ≥ 26.1 with `--experimental-ffi` (auto re-exec injects the flag, see `src/app/runtime.ts`).

**Code comments and the README are written in Simplified Chinese** — keep new comments in Chinese to match.

There is no lint config; `npm run typecheck` is the correctness gate alongside tests — and since it is the only gate, the root tsconfig turns on `noUnusedLocals`/`noUnusedParameters`: a refactor that moves a feature out leaves dead imports and stale references behind, and without those flags nothing catches them (the extension extraction shipped four such files past a green typecheck). `apps/desktop` deliberately does **not** set them — its renderer imports `React` explicitly in every component and `rpc-result-map.test.ts` uses `_name` type-assertion bindings. UI tests need Bun because OpenTUI's test renderer is the real native renderer (FFI); `vitest.ui.config.ts` forces the `bun` export condition and the `bun --bun` prefix forces the Bun runtime (plain `bunx vitest` silently runs Node via the shebang).

Solid JSX cannot be compiled by esbuild — both build lanes run `babel-preset-solid` with `{ moduleName: '@opentui/solid', generate: 'universal' }`: tsup via `esbuild-plugin-solid`, vitest (both configs) via the shared inline plugin in `vitest.solid.ts` (deliberately NOT vite-plugin-solid: it injects jsdom + a `browser` resolve condition that crashes Bun fork workers at boot). **The `solid-js` server-stub trap**: bare `solid-js` resolves to `dist/server.js` (a non-reactive SSR stub — onMount/createEffect are no-ops, so keyboard subscriptions silently die and the first frame looks fine) under Node's `node` condition AND Bun's `worker` condition. Fixes are load-bearing in three places: tsup's `renderChunk` rewrites emitted `"solid-js"` specifiers to `"solid-js/dist/solid.js"`, tsup `noExternal: ['@opentui/solid']` freezes the node variant (which pre-pins the client build) into the TUI chunk (the bun variant imports bare solid-js and relies on an upstream Bun loader plugin we don't ship), and vitest aliases both `solid-js` and `@opentui/solid` to the same pinned files. Single-instance matters: two solid-js copies = signals in one, effects in the other, updates never tracked.

## Architecture

Core principle: **the agent core never imports the UI framework (SolidJS).** `src/core/events.ts` defines the contract — the core emits typed `AgentEvent`s over a minimal `EventBus`. The same agent loop therefore drives both the OpenTUI TUI (`src/ui/App.tsx`) and the non-interactive `-p` renderer (`src/app/headless.ts`).

**Process model (opencode-style client-server).** The TUI is a thin client: by default it spawns a managed `mojocode serve --managed` child (agent core + tools + MCP + LSP + store all live there) and talks REST + SSE — `src/server/serve.ts` (HTTP server, no FFI, Node ≥ 22), `src/server/protocol.ts` (wire types; state snapshots, serialized AgentEvents, deferred call-results), `src/client/remote.ts` (SSE-driven state mirror + serialized RPC queue). The UI consumes the narrow `SessionHandle` interface (`src/app/session-handle.ts`); the local `Session` from bootstrap satisfies it structurally, so UI tests and the `MOJOCODE_NO_SERVER=1` escape hatch run in-process with zero UI changes. `-p` headless stays in-process on purpose (pipe semantics, no HTTP hop). Key invariants (each one is a bug we actually hit — do not regress):
- Long-running calls (`run`/`runSkill`/`compact`) are ACKed immediately and complete via SSE `call-result` (a long-lived POST would trip undici's 300s timeouts). **Optimistic busy flags are set synchronously before the POST, never in the ack's `.then`** — the server's `Agent.run` can return instantly (inject fast path), so `call-result` may land first; the completion handler then clears the flags and the late ack sets them back forever, leaving `isRunning` permanently true and the session unusable. New run-like deferred methods (`runSkill`/`startReview`/`startSimplify`) must be added to **both** `DEFERRED_METHODS` and `RUN_LIKE_METHODS` — the two sets live adjacent in `protocol.ts` exactly so this pairing is visible; missing the latter reproduces the stuck-`isRunning` invariant above.
- `connectRemote` resolves only after the SSE stream is registered server-side (returning earlier loses events broadcast to zero clients).
- **Startup notices are replayed to newly-attached SSE clients** (non-seamless connects only). bootstrap accumulates them in `Session.startupNotices` (disk-extension load failures, missing packages) — **three consumers, all required**: serve (SSE), headless (`bus.on`), and App (drains `SessionHandle.startupNotices` on mount, the only path for in-process `MOJOCODE_NO_SERVER=1`; the field is absent on `RemoteSession` so remote never doubles) because at that moment nothing subscribes to the bus — serve calls `bus.on` after `await bootstrap()`, App subscribes on mount, EventBus has no replay — so an `emit` there would fall on the floor. The client side has the same window: `connectRemote` writes SSE frames onto the bus before App mounts, so remote's bus is a `QueuedEventBus` that queues events until the first subscriber. Tests of this must *actually wait* before subscribing, or the queued half is never exercised.
- RPCs are client-serialized because App issues order-dependent pairs (e.g. `setReasoningEffort` right before `run`; extension commands' `runCommand` rides the same queue).
- Credentials never cross the wire: `redactConfig` covers `providers.*.apiKey`, `search.apiKey` **and `mcpServers.*.env` / `.headers`** (token-carrying by convention) — redaction keeps the field as `''`, so client code tests key presence with `apiKey !== undefined`, never truthiness (the truthy check made `/provider` mark every wizard-configured provider "no key"). The one client→server exception is the picker's just-entered key riding the `switch` RPC, and `remote.ts` refuses it unless the transport is loopback or https (`isTrustedTransport`) — plaintext `serve --host` + `--attach` must not broadcast a fresh key. Every request needs the Bearer token (a localhost server that can run bash is a drive-by target).
- Every awaited session call in the UI needs a `.catch`: they are RPCs now, so transport errors reject and an unhandled rejection kills the TUI (`handleSubmit`'s async IIFE and `/think` were the two that slipped through).
- `pushState` skips pure streaming events (`STATE_NEUTRAL_EVENTS`) — change detection saves the broadcast, not the full config `JSON.stringify` per `text-delta`.
- The managed child exits on stdin EOF **plus** a ppid watchdog (Bun doesn't reliably emit stdin `end` when the parent is SIGKILLed).
- A dead sidecar must leave a cause of death. The serve process registers `unhandledRejection` (log, keep running — one missed `.catch` in agent/MCP/LSP must not kill the session) and `uncaughtException` (log, exit 1) at the top of `runServe`; both spawn sites (`src/app/server-launch.ts` for the TUI, `apps/desktop/src/main/spawn-server.ts` for the GUI) attach a post-handshake `onExit` hook that delivers exit code/signal plus the stderr tail ring buffer, wired to `RemoteSession.notifyServerExit` — which fails fast (no waiting out the 5 reconnect attempts) and puts the death detail on the bus as the non-recoverable error the user sees. Expected shutdowns are absorbed by remote's `closed` idempotency (TUI) and session-service's `disposing` flag (GUI); without the hook a crash is just "connection lost" a few seconds later and the tail buffer is never dumped. GUI wording comes from `notice.serverLostApp`/`notice.serverExitedApp` via `RemoteOptions.lostMessage` — the default strings say "restart the TUI", which is wrong in the app.
- SSE resume: every `event`/`call-result` frame carries a monotonically increasing `id:`; the server keeps a replay ring buffer (1000 msgs / 4MB, both caps needed — deltas are many-and-small, tool outputs can be huge) and a reconnecting client sends `Last-Event-ID` to resume seamlessly. Losing a `call-result` during a disconnect would otherwise leave the client's pending run promise unsettled forever (spinner never stops). Only when the buffer has rolled past the requested seq does the server send `gap` — the client then warns that the transcript is incomplete and refreshes its mirrors. `state` frames carry no id and are never buffered (a fresh snapshot is pushed on every connect); startup notices are re-sent only on non-seamless connects (a seamless resume would double them). External clients: `mojocode serve` standalone + `mojocode --attach <url>` with `MOJOCODE_SERVER_TOKEN`.

commander entry point (subcommands: `auth`, `models`, `providers`, `sessions`, `config`, `doctor`, `serve`, `install`, `remove`, `extensions`). **The TUI is a lazy `import('./ui/tui.js')` behind `loadTuiOrExplain()`** — never import `src/ui/` (→ kit → `@opentui/core`, which needs FFI at module load) statically from `cli.tsx` or anything on the `-p` path; tsup `splitting: true` keeps the TUI in its own chunk so `dist/cli.js` stays FFI-free.

`src/app/doctor.ts` powers both `mojocode doctor` and the TUI's `/doctor`: `collectDoctor()` gathers levelled checks (env / config / provider / search / MCP / sessions / workspace) into a `DoctorReport`, `formatDoctor()` renders it. Check `id`s are the stable contract for `--json` and tests; `label`/`detail` are localized. A `fail` check sets exit code 1. Two things to keep in mind when touching it: commander lets the *root* command swallow `-C` and `--json` when a subcommand declares the same names, so the doctor action reads them off `program.opts()`; and the TUI passes `session.config` plus the mcp extension's published runtime statuses into `runDoctor()` so the report reflects in-session `/model` changes and does **not** re-connect MCP servers (that would spawn a second child process per stdio server). `runtimeOf` returning `undefined` is ambiguous by construction — either nobody published that key, or the publisher had nothing to report — so bootstrap passes `mcpOff` alongside, derived from `extensionRuntime.has(MCP_RUNTIME_KEY)`: under `--no-mcp` nobody publishes, and without the flag doctor read that as "this session checked nothing" and connected every configured stdio server itself, spawning exactly the children this invariant forbids. LSP needs no such flag — its getter returns `undefined` even when the extension is loaded (the manager is lazy), so both readings mean "go probe".

Data flow for one turn: `Agent.run()` (`src/agent/loop.ts`, wraps AI SDK `streamText` with `stepCountIs`) → events stream to the renderer → `onHistoryChange` persists history to an append-only JSONL in `~/.mojocode/sessions/` via `SessionStore` (incremental `append` records when the array is a pure extension of what was last saved — reference-prefix compare — otherwise a full `snapshot`; a `<id>.meta.json` sidecar makes `list()` O(1) per session; session-level state — changed files — rides along as `state` records; 扩展自己的状态(todo 清单、`/goal` 的条件)走 `custom` 记录). The store keeps **two histories**: `messages` (model-facing; compaction replaces the prefix with a summary) and `displayMessages` (never shrunk by compaction — `/resume` replays it so the user sees the original conversation; rewind is a real deletion and trims both). Snapshot records carry a `display` field only when the two differ; legacy files without it are reconstructed by shape (`reconcileDisplay`), and `GET /history` serves both (old servers omit `displayMessages`, clients fall back to `messages`).

**扩展钩子层(Pi 式,`src/core/hooks.ts`)。** 功能从核心搬出去成为扩展靠的是这一层,不是 bus:bus 是同步、单向、给渲染层看的事实流,处理器返回值无意义;钩子异步、按注册顺序串行、返回值有意义。命名用 snake_case(`before_agent_start` / `tool_call` / `tool_result` / `turn_start` / `turn_end` / `agent_end`)与 bus 的 kebab-case 区分。每个输入带 `subagent` 标记——子 agent(task / fork 技能)与主 agent 共享同一份 `HookRegistry`(bootstrap 建一份,`Session.hooks` 暴露,`TaskToolDeps.hooks` 透传),扩展自己决定要不要区别对待。失败策略按钩子性质定,不是一刀切:`tool_call` **失败即否决**(它是做拦截的扩展的落脚点——没有权限系统之后这是唯一的卡口,抛错的处理器若被当成放行,拦截扩展一有 bug 工具就全部裸跑;否决消息点名钩子),`tool_result` / `before_agent_start` 失败保留原值,通知型钩子只上报;所有失败经 `onError` 变成 `notice.hookFailed`,绝不冒泡到循环里。**工具包装在 streamText 边界、每次开流现包**(`src/agent/hooked-tools.ts`,`Agent.hookedTools`):tools 对象会被就地改键(MCP 连上后并入、skill 重建、view_image 增删),提前包好的副本看不见;没有工具钩子时原对象直达 SDK,零开销(`tests/hooks.test.ts` 锁住这两点)。否决/错误的呈现与工具内部抛 Error 一样:抛 Error → SDK tool-error → `tool-end`(isError)喂回模型,整轮不终结。`before_agent_start` 只改**发出去的** system,`options.systemPrompt` 那份核心组装的原文不动,prepareStep 的换提示词判定仍比对原文。**followUp 与 inject 是两种东西**:`inject` 把消息塞进正在跑的这一轮(引导),`Agent.followUp()` 排一条**新的一轮**(自己的 turn-start / turn-end,进时间线与历史),空闲时立即开跑。`run()` 自己排水整个链条——首轮 + turn_end 钩子期间排进来的每一轮——整个链条内 `isRunning` 为真(两轮之间 controller 为空,由 `chainActive` 撑着),期间提交的消息走 inject 进下一轮,绝不并发起第二个链条,一次 run RPC 覆盖整条链、客户端忙碌标记不中途熄灭。这是 goal.ts 曾踩的坑的解法:bus 的 `turn-end` 在 try 里就发出,handler 里 `run()` 会被重入兜底转成 inject 混进上一轮历史;`turn_end` 钩子则在 runTurn 完全返回(finally 已跑、历史已落盘)之后才跑。两轮之间的 `abort()` 记标记、丢掉整个队列并补发 `aborted`;轮内中断/出错同样丢队列——用户刚停下,agent 绝不自己续跑;`agent_end` 带 `followUpsDropped`,扩展靠它知道自己排的续跑没发生。turn_end 期间注入的引导没有 followUp 可搭时以 `GUIDANCE_ONLY` 单独续跑一次(不发 turn-start,它已作为引导回显过)。**自定义会话记录**:`store.saveCustom(type, data)` / `store.custom(type)` / `SessionStore.readCustom`(`kind: 'custom'`,Pi 的 appendEntry):open 时按顺序收进内存,恢复回放不看,旧版本静默跳过,**分叉整体带过去**(扩展的状态与 state 同属会话),`custom()` 返回深拷贝。

**`/simplify` 与 `task` 明确留在核心,拆分到此为止**——这是查过五家竞品之后的决定,不是没拆完的债。pi / opencode / Claude Code / Codex / Cline **没有一家**在 extension/plugin API 上挂 `spawnSubagent()`:定义永远是声明式文件(`.claude/agents/*.md`、`.codex/agents/*.toml`、opencode 的 `agent` 段),发起永远是宿主内建的、模型可调用的工具(`task` / `Agent` / `spawn_agent` / `use_subagents`),Codex 甚至明写拒绝 —— 它解析了 Claude Code 的 hook schema 却把 `agent` 型 handler「parsed but skipped」。pi 连核心里都不做子代理,唯一的实现是个 example extension,用 `spawn()` 起 `pi -p` 子进程,代价是 frontmatter 解析、user/project scope、信任确认全得扩展自己重写一遍。我们现在的形状(`task` 是宿主内建工具、`runTaskSubagent` 在三个消费方之间 deps-injected)**已经就是行业默认**,那是收敛点而不是债。`/simplify` 要编排四个并行 explore 子代理、合成工具事件、给失败的轴留位置——那是宿主编排,不是策略。真正与竞品有差距的地方在别处:我们的 `TaskMode` 是写死的 `'general' | 'explore'` 两档,模型与步数都不能按 agent 定,而五家的 agent 定义字段高度趋同(身份 + 系统提示词 + 模型 + 推理档位 + 工具/权限范围 + 步数上限)。要在子代理上投入,该投的是声明式 agent 定义,不是扩展 API。

Module map:

- `src/config/` — layered config: builtin defaults → `~/.mojocode/config.json` → `<root>/.mojocode/config.json` → `MOJOCODE_*` env vars → CLI flags. `providers.<id>.models` is the GUI-maintained per-provider model list (`{id, label?, contextWindow?, maxOutputTokens?}[]`): the desktop model picker reads it synchronously (zero probing) and falls back to `/models` endpoint probing only when no provider has one; when other providers have lists but the *active* provider doesn't, `configuredModelGroups` synthesizes a group holding just the currently-running model (never a preset list — those go stale) so the active provider can't vanish from the picker; `resolveProvider` prefers a matching entry's `contextWindow` (normalized-id match) over the provider-level `contextWindow`, and resolves the entry's `maxOutputTokens` onto `ResolvedProvider` (optional field), which the agent loop passes straight to `streamText` — the GUI add-model dialog's「高级 · 最大输出 Token」is real, not decorative. A model entry's `reasoning` field takes two shapes: an effort string (per-model default effort, beats `providers.<id>.reasoningEffort` and the global default, still translated by `reasoningMapping` and still adjustable via /think) or a **custom params object** — resolved onto `ResolvedProvider.reasoningParams` and merged verbatim into `providerOptions` under the provider key, fully REPLACING the effort mapping (for thinking knobs the family table can't express: Qwen `enable_thinking`, vLLM `chat_template_kwargs`, gateway `reasoning: {...}`). With custom params, effort presets and /think are dead for that model — the desktop composer's effort chip therefore shows「自定义」with no menu instead of a fake picker (the deepseek dedicated SDK only passes its canonical keys through, so arbitrary custom params silently drop there). **Which levels are selectable comes from `src/model/catalog.ts`** — a pruned, disk-cached (`~/.mojocode/cache/models-dev.json`, 24h TTL, stale-on-failure, 5min retry backoff) mirror of models.dev's per-model `reasoning_options`/`limit`, surfaced as the `modelCapabilities(providerId, modelId)` Session RPC. 'auto' (send no thinking params — the untouched default) is NOT a listed level anywhere by user decision: `effortChoices` excludes it, `reasoningMenuEntries` and the TUI /think picker filter it, the composer chip still *reads*「自动」to describe the untouched state, and a bare `/think auto` remains accepted as the only way back to send-nothing; a model whose catalog efforts come back empty (no reasoning at all) hides the composer thinking chip entirely. Consumers: TUI /think picker + validation, the desktop composer's reasoning menu, and the add/edit-model dialog (prefills the context window, shows a catalog hint line, narrows the thinking select — which deliberately omits「自动」(「默认(跟随会话档位)」already means "don't pin anything") and **preselects the middle of the catalog's effort ladder** ('off' excluded as not-an-intensity, even count rounds down: low/high/max → high) so saving writes that level explicitly; an entry with an existing explicit choice or a user-touched select is never overridden); everywhere the catalog misses (custom local endpoints, offline first run) falls back to `supportedEfforts`' family table — the catalog provides *which levels exist*, `reasoningMapping` still owns *how to encode them on the wire*. That reconciliation happens in **one** place, `effectiveEfforts` (reasoning.ts), called by bootstrap's `modelCapabilities` so all three frontends render a ready-made list — putting it in the frontends was wrong twice over: the family table is a server-only module the renderer cannot reach, so the same catalog gap narrowed the TUI while the GUI listed levels the model does not support. Two traps it exists to close. `effortChoices` is **tri-state** and collapsing it loses thinking control entirely: `[]` means the catalog says the model does not reason (composer hides the thinking chip), a non-empty array is the catalog's ladder, and `undefined` means the catalog knows it reasons but never described the shape — a *gap*, not an absence, and the majority case upstream (~1400 entries incl. `deepseek-reasoner` and `kimi-for-coding`), so it must fall back to the family table; `??` does that for `undefined` and, crucially, not for `[]`. And catalog levels are intersected with what the wire can actually carry: `unsupported` levels are dropped (kimi k3's `off` is listed by the catalog but `reasoningMapping` emits nothing for it, so picking it left thinking on), while `coarse` ones are kept (GLM-4-class toggle-only models: a level at least means "thinking on"). `effectiveEfforts` also strips `auto` on the fallback path, since the family table counts it as supported. GLM-5+ models (`isGlmEffortModel`) send a real `reasoning_effort` alongside `thinking:{enabled}` — verified against the live Coding Plan endpoint: an invalid value 400s listing `none…max`, and low vs max measurably changes reasoning tokens (0 vs 44); GLM-4 stays toggle-only. Don't regress this to "GLM only has a switch". Preset ids map to models.dev ids via `PRESET_CATALOG_IDS`; unmapped providers fall back to a whole-catalog model-id match preferring reasoning-rich entries. Writes go through `saveProviderEntry`/`deleteProviderEntry` (save.ts) — merge-by-key, `undefined` values skipped, because the GUI only ever sends the keys the user actually edited (its config copy is redacted; echoing it back wholesale would blank real keys). Session exposes them as `saveProvider(id, patch)` / `deleteProvider(id)` (bootstrap validates the patch through `providerConfigSchema` to strip unknown wire keys; deleting the *active* provider is refused; editing the active one re-resolves best-effort via an empty `switch`), served as instant RPCs in serve.ts (the post-dispatch `pushState` broadcasts the updated redacted config) and mirrored on `RemoteSession` with the same `isTrustedTransport` guard as `switch` when the patch carries an `apiKey`. Zod schemas in `schema.ts`; provider presets (baseURL, key env vars, default models) in `providers.ts`; web-search backend presets (GLM standalone search endpoint / Exa / custom) in `search.ts` — `resolveSearchBackend` returns `undefined` on a missing key (never `MissingKeyError`, which would trigger the auth wizard) so `web_search` degrades to "not registered". **zod 4 layer trap**: `.partial()` does NOT strip `.default()` — a layer file's *missing* keys come back filled with phantom defaults (`provider:'deepseek'`, `language:'auto'`, …), and since layers merge by priority, a project layer's mere *existence* (e.g. one written by `mojocode install --local`) silently reset every global-layer default-carrier on every startup (the "switched model reverts after restart" bug). Two defenses, both load-bearing: `partialConfigSchema` is hand-written all-optional (new defaulted fields in `configSchema` MUST be mirrored there), and `readLayer` filters parsed output down to the keys actually written in the file.

- `src/ui/` — **SolidJS** (`@opentui/solid` 0.5.1, exact-pinned with `@opentui/core`, `solid-js` and `web-tree-sitter` — the same stack opencode ships) components in alternate-screen fullscreen mode. `kit.tsx` is the renderer adapter: Ink-shaped `Box`/`Text`/`useInput`/`useApp`/`render` over OpenTUI — components import kit, never `@opentui/*` directly (upstream 0.x breakage lands in one file). Kit absorbs the semantic gaps: OpenTUI `<text>` does not parse ANSI (kit's `Text` routes ESC-containing strings through `ansi-spans.ts` → `<span>`s; SGR 39/49 mean "inherit outer", which Diff's background highlight relies on); nested `<Text>` must be `<span>` (context-switched — and children resolution must happen INSIDE the provider, Solid's `children()` helper is eager); **span (TextNode) styles only apply via the `style` prop** (`style={{fg,bg,bold…}}`) — direct `fg=`/`bg=` attrs are silently ignored by the upstream reconciler, and the failure mode is text silently rendering in default white; plain printable keypresses in one synchronous burst are still merged into a single `input` dispatch (collapses N renders; the React-era flushSync/stale-closure machinery is gone — Solid handlers read signals live). Mouse is on (OpenTUI's `useMouse` defaults to true — that's what makes wheel-scroll and `useSelectionCopy`'s drag-select work), and kit exposes it as one prop: `onClick` on `Text`/`Box`, wired to `onMouseDown`/`onMouseUp` via `clickHandlers`. Four rules there, all load-bearing: a click is **down and up on the exact same cell** — anything looser (same row, same element) turns a horizontal drag-to-copy into a click, i.e. a mis-click that picks a row (the rewind picker truncating history); the pending down-cell lives in a **per-renderer** `PointerState` (WeakMap), never per-element — an element that is pressed and then dragged away from never receives its own `up`, so per-element coordinates stay armed forever and the *next* drag that merely ends on that cell fires its `onClick` (verified repro: drag row1→row2, then drag elsewhere→row1, and row1's option decides); a click is also refused when the element **mounted after the previous click and within `CLICK_SETTLE_MS` (250ms)** — clicking a row usually swaps what occupies those same cells, so a double-click's second press lands on the freshly revealed row and applies it (double-clicking `/setting` → Language silently switched the locale to whatever row landed there). That window is per-renderer too, or tests leak it into each other's first click; UI tests that click twice in sequence must sleep past it. And `onClick` on a *nested* `<Text>` is dead, since those render as `<span>`/TextNode, which is not a Renderable and never enters the hit grid — it goes on the row's outermost `Text`, which a column container stretches to full width, so the whole row (trailing blank space included) is the hit area with no extra wrapper Box. List panels (`SettingsPanel`, `RewindPicker`, `SessionPicker`) route click through the same action as the key binding, never a separate path; (`ModePicker.tsx`, `ReviewPicker.tsx` and `PermissionPrompt.tsx` are all gone — the first two were second implementations of a picker the generic selector already draws, the third went with the permission system.) Clicking must never do more than the keyboard can (`/setting`'s status-bar section is multi-select, so a row click toggles the draft and only enter commits). Keyboard stays the only guaranteed input (SSH, mouse-less terminals) — click is strictly additive. Kit's other mouse prop is `onScroll` (Box only): one cursor step per wheel event, deliberately ignoring `ScrollInfo.delta` (terminals send an event per notch; scaling by delta makes a list fly past), and it `stopPropagation`s so wheeling a menu never also scrolls the timeline underneath. Input's three lists (`/` command menu, `@` file menu, the multi-level arg selector) already windowed at 8 rows with more-above/below hints — wheel and ↑/↓ go through the *same* `moveMenu`/`moveFileMenu`/`moveSelector` movers so wrap-around is identical; a wheel that clamped while the arrow key wrapped would be two feels for one list. The *timeline* does not use upstream's wheel handling at all: `attachSmoothScroll` overrides the scrollbox's `onMouseEvent` (per-instance, same trick as `handleKeyPress` above) so a notch only moves a **target** position, and a frame callback eases the real `scrollTop` toward it. Two upstream facts force this. First, `ScrollInfo.delta` is hardcoded to 1 by the mouse parser and the default `LinearScrollAccel` returns a flat multiplier of 1, so one notch = one line — dozens of flicks to get back a few screens (`scrollAcceleration` is upstream's only knob, and `MacOSScrollAccel` is not a fix: its base is still 1, so it addresses "scrolling for a long time", not "one notch does too little"). Second, upstream applies the step *instantly*, so any step bigger than a line is a visible jump — raising the step alone buys speed at the cost of smoothness (this is exactly what opencode's default 3-lines-per-notch feels like, and why it still reads as steppy). So `StreakScrollAccel` sets the target (3 lines/notch, +1 per notch within an 80ms streak, capped at 8) and the easing (`1 - e^(-dt/55ms)`, floor of one line per frame — the terminal's minimum unit; a proportional tail would otherwise grind at sub-line speed forever) spends it over several frames. `requestLive()` runs only while the animation does (`dropLive()` on landing), so the renderer is back to on-demand at rest — and `targetFps: 60` in `render()` exists **for this animation only**: it is the frame rate of a live loop, while on-demand renders are already capped by `maxFps` 60. Ordering matters at rest: sticky-follow moves `scrollTop` behind our back, so a frame that sees a value it did not write abandons the animation and re-syncs, and a notch arriving while idle re-seeds position/target/written from the box (all three — seeding only two makes the very first frame after a sticky jump look external and swallow the gesture). Page/Home/End stay upstream's instant behavior, but stop the easing first or the two fight over `scrollTop`. A menu is still exactly one row per notch, instantly — a list you pick from has no "fast" mode and no animation. `tests/support/otui.tsx` exposes `click(x, y)` and `scroll(x, y, dir)` over the upstream `createMockMouse`. Solid discipline: never destructure props; derived values are functions/memos; multi-signal updates that an effect observes must be `batch()`ed (the pasted-image pruning effect bug). Switching the language (`/setting` → Language) re-evaluates static strings by keyed-remounting the JSX body while all signals live outside it — the `<Show when={locale()} keyed>` child callback **must declare a parameter**: Solid's `Show` gates the by-value call on `children.length > 0`, so a zero-arity arrow is returned as a plain reactive child, the memo keeps handing back the same function reference, and nothing rebuilds (the language flips but every static string stays in the old locale). `SettingsPanel.tsx` is the `/setting` panel — a two-level modal (section list → per-section editor: language single-select, status bar multi-select over a draft set so esc discards) rendered in the same mutually-exclusive branch as `PermissionPrompt`/`RewindPicker`, i.e. Input is unmounted and its own `useInput` owns the keyboard. New user-facing settings go in there, not into new slash commands (`/lang` and `/statusbar` were folded into it). Timeline is a `<scrollbox stickyStart="bottom">` (`ScrollArea` — the flexGrow/flexShrink/flexBasis:0/minHeight:0 quartet is load-bearing); items are immutable so `<For>` reuses entries with zero re-render (React.memo's job, now free), `renderMarkdownAnsi` stays LRU-cached by `(item.key, width)` in `md-cache.ts`. `/focus` (`focus.ts` `collapseItems`) filters the timeline at render time — `user`/`assistant`/`error`/`banner` and ALL notices are NEVER hidden (iron law, locked by `tests/focus.test.ts`). Two orthogonal collapse axes, don't conflate them: `/focus` hides whole *entries*; **ctrl+r** (`detailsExpanded` in App, passed down as `TimelineEntry`'s `expanded` prop) toggles the *bodies* of reasoning and raw tool output, which are collapsed by default (`+ N lines` placeholder) — diff/plan/todo bodies are results, not process noise, and are never collapsed (same line focus.ts draws). Every turn ends with a `kind: 'turn'` line (model · elapsed · that turn's tokens, from the cumulative delta measured at `turn-start`); aborted/error turns have their own line and don't get one. Single-line info rows must be measured and cut before layout — an overflowing OpenTUI flex row shrinks its children and silently eats the spaces around separators, so `Footer.fitParts` narrows cwd first, then gives it its own row, then drops segments by priority. Footer is a two-group status bar — left (model / cwd / think), right (context meter / total) — and the gap between the groups is an explicitly computed run of spaces, **not** `justifyContent`: flex's space-between shrinks children on overflow, i.e. the exact failure fitParts exists to prevent, so "never overflows" stays the job of one function. Overflow never promotes the right group to its own row (segments get dropped instead) — every extra footer row costs the timeline one. Context is a `meterBar` (`▰▱`) that lights the first cell at any non-zero use and never fills the last cell below 100% (a full bar means "at the ceiling"), and NaN is clamped at the door or the bar silently collapses to zero columns. The work-status row is the **input box's top edge**, not a row above it (Codex-style): `Input` draws only its bottom border via kit's `borderSides={['bottom']}` (kit re-exports OpenTUI's own side union; a box with no left/right sides renders no corners, so `borderStyle="round"` is harmless) and renders that edge in one of two forms — `StatusLine` (`── ⠋ 思考中 · 12s · esc 中断 ───…`) while working, `IdleRule` (a plain full-width rule) when idle. **The caller picks; neither component knows the other exists** — `StatusLine.work` is required, so it carries no idle branch, and its timer lives at component scope because it only exists while working. Both take the color `Input` already hands its `<Box borderColor>`, so "this rule IS the border" is one expression used twice rather than two chains that drift (`phaseColor` exports the phase table for that one caller). `Input` reads its own width via kit's `useTerminalSize` (same as `PermissionPrompt`) instead of taking a `columns` prop — a stale width here is a wrapped row. It measures too: the tail (elapsed / turn tokens / ctrl+t / esc) drops by priority against `columns - 5` (lead `── ` plus a minimum ` ─` trail) and the rest of the row is filled with `─`, all in **one** `parts()` memo — the earlier chain of mutually-calling accessors re-measured the same strings ~23 times per frame, and this row repaints every 100ms where a wrap makes the whole bottom block jitter once a second. Full-width (last column included) is required because the native bottom border is full-width; the anti-wrap defense is `wrap="truncate-end"`, not a reserved column (`WIDTH_SAFETY`'s usual rule), since every glyph here is East-Asian Ambiguous and a ±1 disagreement must degrade to a clipped right end, never to a second row. The line is self-drawn on purpose: OpenTUI's native box `title` *drops* an over-wide title instead of truncating it, and it is single-color (the dim tail would be lost). Overlays (pickers, settings) and Input's own enum selector replace the box, so App and Input mount `StatusLine` above them **only while working** — an idle overlay needs no rule (the rule is the input's edge, not a separator) — with no blank line between the status band and the overlay's `╭` (locked by `tests/ui/app-layout.test.tsx`). Those `<Show>`s are written inline at each site and share only a props memo: returning a `<Show>` from a helper function called as `{helper(...)}` in JSX does **not** insert as a dynamic child under the universal transform — the branch switches, the old component is disposed, and its node stays on screen frozen at the last frame (the status line kept spinning `running slowTool` after abort). `Header`'s title is a pixel-font logo (`logo.ts`: a 5×5 dot-matrix font squeezed into 3 text rows with half-blocks `▀▄█`, one gradient color per letter — the row is split per character because a single `<Text>` can only carry one color); it needs `pixelLogoWidth(APP_NAME) + 4` columns (border + paddingX) and falls back to the plain bold name below that — a wrapped half-block glyph shatters into noise, so the block is all-or-nothing, and `TimelineEntry` must keep passing `columns` down for the check to work. ## Gotchas (do not regress)

- GLM's baseURL is `/api/paas/v4` — never append `/v1` (404s).
- Never hardcode model IDs; presets are only starting defaults, `mojocode models` fetches the live list.
- Use `result.responseMessages` for history, not `result.response.messages` — the latter only contains the last step and silently drops earlier tool calls.
- Kit's `render()` defaults `exitOnCtrlC: false` — the renderer would otherwise destroy itself before `useInput` sees ctrl+c, breaking the double-ctrl+c-to-exit logic (startup wizard/picker opt back in).
- Cross-compiling needs the target's `@opentui/core-<platform>` package on disk; `build-binaries.ts` installs missing ones on demand (`npm install --no-save --force`). Do NOT pin them in package.json — each declares os/cpu, so a bare `npm ci` would EBADPLATFORM on every machine. The script also pins `process.env.OPENTUI_LIBC` per Linux target via define — without it both glibc and musl native libs get embedded (+~18MB).
- In-turn compaction only shrinks the messages sent to the model; the persistent history stays long, and the `historyNeedsCompact` flag forces compaction at the next turn start (otherwise the shrunken `lastInputTokens` masks the need). The same flag also covers the *other* blind spot: `setHistory` (resume, rewind) invalidates `lastInputTokens`, and `shouldCompact(undefined, …)` is `false`, so the swapped-in history would go out verbatim. Since **resume no longer switches back to the session's recorded provider/model** (it keeps whatever the current config resolves — ``resumeOverrides` is gone), a long history can land on a smaller window and 400 on the first turn, identically on every retry. `setHistory` therefore seeds the flag from `estimateTokens` (CJK ≈ 1 token, else ¼, images stripped) — a local estimate used **only to trigger** compaction, never to conclude none is needed: under-estimating falls back to the old behavior, over-estimating costs one extra summary. `meta.provider`/`meta.model` are now display-only (session picker, `mojocode sessions`) and are kept current via `store.setModel` on switch/resume.
- `src/config/paths.ts` resolves the home dir from `$HOME`/`$USERPROFILE` first, **never bare `os.homedir()`** — Bun snapshots the home dir at startup and ignores later `process.env.HOME` mutations, so the single binary would put `~/.mojocode` somewhere else than the Node build whenever HOME is set explicitly (containers/CI), and tests that mock HOME silently read the developer's real config instead.
- Node floor is **22**, not 20: execa 10 calls `Set.prototype.union` (ES2024) at import time, so Node 20 dies before `--version` prints. `engines`, the CI matrix and the README all say 22 — keep them in sync if a dependency raises the floor again.
- `vitest.config.ts` (core lane) carries the same `zod` → `index.cjs` and `solid-js` → `dist/solid.js` aliases as the UI config: CI also runs the core suite under Bun (`bun --bun x vitest run`) to guard dual-runtime compat, and without the aliases `import { z }` is undefined there.
