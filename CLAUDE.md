# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`mojocode` — a terminal coding agent (full-screen OpenTUI TUI + headless `-p` mode) that works with any LLM via the Vercel AI SDK (Kimi / DeepSeek / GLM presets + any OpenAI-compatible endpoint). ESM-only, TypeScript with `strict` and `noUncheckedIndexedAccess`. Runtime split: `-p`/subcommands run on Node ≥ 22; the TUI needs native FFI — Bun (primary, single-binary distribution) or Node ≥ 26.1 with `--experimental-ffi` (auto re-exec injects the flag, see `src/app/runtime.ts`).

**Code comments and the README are written in Simplified Chinese** — keep new comments in Chinese to match.

## Commands

```bash
npm run build       # tsup → dist/cli.js + lazy chunks (esm, splitting on, deps external)
npm run dev         # tsup --watch
npm run typecheck   # tsc --noEmit (tsup does not typecheck)
npm test            # core tests, Node lane (excludes tests/ui/)
npm run test:ui     # UI tests, MUST run under Bun (= bun --bun x vitest run --config vitest.ui.config.ts)
npm run build:bin   # bun scripts/build-binaries.ts — cross-compile single binaries (6 platforms)
npx vitest run tests/gate.test.ts          # single core test file
bun --bun x vitest run --config vitest.ui.config.ts tests/ui/input.test.tsx   # single UI test file
node dist/cli.js    # run the built CLI (or `mojocode` after npm link)
cd apps/desktop && npm run typecheck   # Electron GUI — separate package; root npm ci required (@core/* compiles root src/)
cd apps/desktop && npm test            # GUI tests (bridge/reducer/components; never launch Electron)
```

There is no lint config; `npm run typecheck` is the correctness gate alongside tests. UI tests need Bun because OpenTUI's test renderer is the real native renderer (FFI); `vitest.ui.config.ts` forces the `bun` export condition and the `bun --bun` prefix forces the Bun runtime (plain `bunx vitest` silently runs Node via the shebang).

Solid JSX cannot be compiled by esbuild — both build lanes run `babel-preset-solid` with `{ moduleName: '@opentui/solid', generate: 'universal' }`: tsup via `esbuild-plugin-solid`, vitest (both configs) via the shared inline plugin in `vitest.solid.ts` (deliberately NOT vite-plugin-solid: it injects jsdom + a `browser` resolve condition that crashes Bun fork workers at boot). **The `solid-js` server-stub trap**: bare `solid-js` resolves to `dist/server.js` (a non-reactive SSR stub — onMount/createEffect are no-ops, so keyboard subscriptions silently die and the first frame looks fine) under Node's `node` condition AND Bun's `worker` condition. Fixes are load-bearing in three places: tsup's `renderChunk` rewrites emitted `"solid-js"` specifiers to `"solid-js/dist/solid.js"`, tsup `noExternal: ['@opentui/solid']` freezes the node variant (which pre-pins the client build) into the TUI chunk (the bun variant imports bare solid-js and relies on an upstream Bun loader plugin we don't ship), and vitest aliases both `solid-js` and `@opentui/solid` to the same pinned files. Single-instance matters: two solid-js copies = signals in one, effects in the other, updates never tracked.

## Architecture

Core principle: **the agent core never imports the UI framework (SolidJS).** `src/core/events.ts` defines the contract — the core emits typed `AgentEvent`s over a minimal `EventBus` and awaits permission decisions through a `PermissionAsker` callback. The same agent loop therefore drives both the OpenTUI TUI (`src/ui/App.tsx`) and the non-interactive `-p` renderer (`src/app/headless.ts`).

**Process model (opencode-style client-server).** The TUI is a thin client: by default it spawns a managed `mojocode serve --managed` child (agent core + tools + MCP + LSP + store all live there) and talks REST + SSE — `src/server/serve.ts` (HTTP server, no FFI, Node ≥ 22), `src/server/protocol.ts` (wire types; state snapshots, serialized AgentEvents, deferred call-results), `src/client/remote.ts` (SSE-driven state mirror + serialized RPC queue). The UI consumes the narrow `SessionHandle` interface (`src/app/session-handle.ts`); the local `Session` from bootstrap satisfies it structurally, so UI tests and the `MOJOCODE_NO_SERVER=1` escape hatch run in-process with zero UI changes. `-p` headless stays in-process on purpose (pipe semantics, no HTTP hop). Key invariants (each one is a bug we actually hit — do not regress):
- Long-running calls (`run`/`goalRun`/`compact`) are ACKed immediately and complete via SSE `call-result` (a long-lived POST would trip undici's 300s timeouts). **Optimistic busy flags are set synchronously before the POST, never in the ack's `.then`** — the server's `Agent.run` can return instantly (inject fast path), so `call-result` may land first; the completion handler then clears the flags and the late ack sets them back forever, leaving `isRunning` permanently true and the session unusable. New run-like deferred methods (`runSkill`/`startReview`/`startSimplify`) must be added to **both** `DEFERRED_METHODS` and `RUN_LIKE_METHODS` — the two sets live adjacent in `protocol.ts` exactly so this pairing is visible; missing the latter reproduces the stuck-`isRunning` invariant above.
- `connectRemote` resolves only after the SSE stream is registered server-side (returning earlier loses events broadcast to zero clients).
- **Permission requests are replayed to newly-attached SSE clients**, and the client queues them until `setAsker` registers. A request is broadcast once; if nobody is listening at that instant (reconnect window, `--attach` to a mid-turn server), the gate `await`s forever and the whole turn hangs.
- RPCs are client-serialized because App issues order-dependent pairs (`goal.set` then `goal.run`).
- Credentials never cross the wire: `redactConfig` covers `providers.*.apiKey`, `search.apiKey` **and `mcpServers.*.env` / `.headers`** (token-carrying by convention) — redaction keeps the field as `''`, so client code tests key presence with `apiKey !== undefined`, never truthiness (the truthy check made `/provider` mark every wizard-configured provider "no key"). The one client→server exception is the picker's just-entered key riding the `switch` RPC, and `remote.ts` refuses it unless the transport is loopback or https (`isTrustedTransport`) — plaintext `serve --host` + `--attach` must not broadcast a fresh key. Every request needs the Bearer token (a localhost server that can run bash is a drive-by target).
- Every awaited session call in the UI needs a `.catch`: they are RPCs now, so transport errors reject and an unhandled rejection kills the TUI (`handleSubmit`'s async IIFE and `/think` were the two that slipped through).
- `pushState` skips pure streaming events (`STATE_NEUTRAL_EVENTS`) — change detection saves the broadcast, not the full config `JSON.stringify` per `text-delta`.
- The managed child exits on stdin EOF **plus** a ppid watchdog (Bun doesn't reliably emit stdin `end` when the parent is SIGKILLed).
- A dead sidecar must leave a cause of death. The serve process registers `unhandledRejection` (log, keep running — one missed `.catch` in agent/MCP/LSP must not kill the session) and `uncaughtException` (log, exit 1) at the top of `runServe`; both spawn sites (`src/app/server-launch.ts` for the TUI, `apps/desktop/src/main/spawn-server.ts` for the GUI) attach a post-handshake `onExit` hook that delivers exit code/signal plus the stderr tail ring buffer, wired to `RemoteSession.notifyServerExit` — which fails fast (no waiting out the 5 reconnect attempts) and puts the death detail on the bus as the non-recoverable error the user sees. Expected shutdowns are absorbed by remote's `closed` idempotency (TUI) and session-service's `disposing` flag (GUI); without the hook a crash is just "connection lost" a few seconds later and the tail buffer is never dumped. GUI wording comes from `notice.serverLostApp`/`notice.serverExitedApp` via `RemoteOptions.lostMessage` — the default strings say "restart the TUI", which is wrong in the app.
- SSE resume: every `event`/`call-result` frame carries a monotonically increasing `id:`; the server keeps a replay ring buffer (1000 msgs / 4MB, both caps needed — deltas are many-and-small, tool outputs can be huge) and a reconnecting client sends `Last-Event-ID` to resume seamlessly. Losing a `call-result` during a disconnect would otherwise leave the client's pending run promise unsettled forever (spinner never stops). Only when the buffer has rolled past the requested seq does the server send `gap` — the client then warns that the transcript is incomplete and refreshes its mirrors. `state` frames carry no id and are never buffered (a fresh snapshot is pushed on every connect); pending permission requests are re-sent from the broker only on non-seamless connects (a seamless resume would double-ask). External clients: `mojocode serve` standalone + `mojocode --attach <url>` with `MOJOCODE_SERVER_TOKEN`.

Wiring happens in `src/app/bootstrap.ts`: it builds the `Session` object (agent + bus + gate + tools + MCP connections + session store) that both frontends consume; `setReasoningEffort`/`listModels`/`doctor` are Session methods (not direct field pokes from the UI) precisely so the remote mirror can RPC them. `src/cli.tsx` is the commander entry point (subcommands: `auth`, `models`, `providers`, `sessions`, `config`, `doctor`, `serve`). **The TUI is a lazy `import('./ui/tui.js')` behind `loadTuiOrExplain()`** — never import `src/ui/` (→ kit → `@opentui/core`, which needs FFI at module load) statically from `cli.tsx` or anything on the `-p` path; tsup `splitting: true` keeps the TUI in its own chunk so `dist/cli.js` stays FFI-free.

`src/app/doctor.ts` powers both `mojocode doctor` and the TUI's `/doctor`: `collectDoctor()` gathers levelled checks (env / config / provider / search / permissions / MCP / sessions / workspace) into a `DoctorReport`, `formatDoctor()` renders it. Check `id`s are the stable contract for `--json` and tests; `label`/`detail` are localized. A `fail` check sets exit code 1. Two things to keep in mind when touching it: commander lets the *root* command swallow `-C` and `--json` when a subcommand declares the same names, so the doctor action reads them off `program.opts()`; and the TUI passes `session.config` plus `session.mcpStatuses` into `runDoctor()` so the report reflects in-session `/approvals`, `/model` changes and does **not** re-connect MCP servers (that would spawn a second child process per stdio server).

Data flow for one turn: `Agent.run()` (`src/agent/loop.ts`, wraps AI SDK `streamText` with `stepCountIs`) → tools call `PermissionGate` inside their `execute()` (deliberately *not* AI SDK `toolApproval`, which would suspend the stream) → gate consults mode/rules or emits `permission-request` and awaits the asker → events stream to the renderer → `onHistoryChange` persists history to an append-only JSONL in `~/.mojocode/sessions/` via `SessionStore` (incremental `append` records when the array is a pure extension of what was last saved — reference-prefix compare — otherwise a full `snapshot`; a `<id>.meta.json` sidecar makes `list()` O(1) per session; session-level state — todos, session allow rules, permission mode — rides along as `state` records). The store keeps **two histories**: `messages` (model-facing; compaction replaces the prefix with a summary) and `displayMessages` (never shrunk by compaction — `/resume` replays it so the user sees the original conversation; rewind is a real deletion and trims both). Snapshot records carry a `display` field only when the two differ; legacy files without it are reconstructed by shape (`reconcileDisplay`), and `GET /history` serves both (old servers omit `displayMessages`, clients fall back to `messages`).

Module map:

- `src/config/` — layered config: builtin defaults → `~/.mojocode/config.json` → `<root>/.mojocode/config.json` → `MOJOCODE_*` env vars → CLI flags. `providers.<id>.models` is the GUI-maintained per-provider model list (`{id, label?, contextWindow?, maxOutputTokens?}[]`): the desktop model picker reads it synchronously (zero probing) and falls back to `/models` endpoint probing only when no provider has one; when other providers have lists but the *active* provider doesn't, `configuredModelGroups` synthesizes a group holding just the currently-running model (never a preset list — those go stale) so the active provider can't vanish from the picker; `resolveProvider` prefers a matching entry's `contextWindow` (normalized-id match) over the provider-level `contextWindow`, and resolves the entry's `maxOutputTokens` onto `ResolvedProvider` (optional field), which the agent loop passes straight to `streamText` — the GUI add-model dialog's「高级 · 最大输出 Token」is real, not decorative. A model entry's `reasoning` field takes two shapes: an effort string (per-model default effort, beats `providers.<id>.reasoningEffort` and the global default, still translated by `reasoningMapping` and still adjustable via /think) or a **custom params object** — resolved onto `ResolvedProvider.reasoningParams` and merged verbatim into `providerOptions` under the provider key, fully REPLACING the effort mapping (for thinking knobs the family table can't express: Qwen `enable_thinking`, vLLM `chat_template_kwargs`, gateway `reasoning: {...}`). With custom params, effort presets and /think are dead for that model — the desktop composer's effort chip therefore shows「自定义」with no menu instead of a fake picker (the deepseek dedicated SDK only passes its canonical keys through, so arbitrary custom params silently drop there). **Which levels are selectable comes from `src/model/catalog.ts`** — a pruned, disk-cached (`~/.mojocode/cache/models-dev.json`, 24h TTL, stale-on-failure, 5min retry backoff) mirror of models.dev's per-model `reasoning_options`/`limit`, surfaced as the `modelCapabilities(providerId, modelId)` Session RPC. 'auto' (send no thinking params — the untouched default) is NOT a listed level anywhere by user decision: `effortChoices` excludes it, `reasoningMenuEntries` and the TUI /think picker filter it, the composer chip still *reads*「自动」to describe the untouched state, and a bare `/think auto` remains accepted as the only way back to send-nothing; a model whose catalog efforts come back empty (no reasoning at all) hides the composer thinking chip entirely. Consumers: TUI /think picker + validation, the desktop composer's reasoning menu, and the add/edit-model dialog (prefills the context window, shows a catalog hint line, narrows the thinking select — which deliberately omits「自动」(「默认(跟随会话档位)」already means "don't pin anything") and **preselects the middle of the catalog's effort ladder** ('off' excluded as not-an-intensity, even count rounds down: low/high/max → high) so saving writes that level explicitly; an entry with an existing explicit choice or a user-touched select is never overridden); everywhere the catalog misses (custom local endpoints, offline first run) falls back to `supportedEfforts`' family table — the catalog provides *which levels exist*, `reasoningMapping` still owns *how to encode them on the wire*. That reconciliation happens in **one** place, `effectiveEfforts` (reasoning.ts), called by bootstrap's `modelCapabilities` so all three frontends render a ready-made list — putting it in the frontends was wrong twice over: the family table is a server-only module the renderer cannot reach, so the same catalog gap narrowed the TUI while the GUI listed levels the model does not support. Two traps it exists to close. `effortChoices` is **tri-state** and collapsing it loses thinking control entirely: `[]` means the catalog says the model does not reason (composer hides the thinking chip), a non-empty array is the catalog's ladder, and `undefined` means the catalog knows it reasons but never described the shape — a *gap*, not an absence, and the majority case upstream (~1400 entries incl. `deepseek-reasoner` and `kimi-for-coding`), so it must fall back to the family table; `??` does that for `undefined` and, crucially, not for `[]`. And catalog levels are intersected with what the wire can actually carry: `unsupported` levels are dropped (kimi k3's `off` is listed by the catalog but `reasoningMapping` emits nothing for it, so picking it left thinking on), while `coarse` ones are kept (GLM-4-class toggle-only models: a level at least means "thinking on"). `effectiveEfforts` also strips `auto` on the fallback path, since the family table counts it as supported. GLM-5+ models (`isGlmEffortModel`) send a real `reasoning_effort` alongside `thinking:{enabled}` — verified against the live Coding Plan endpoint: an invalid value 400s listing `none…max`, and low vs max measurably changes reasoning tokens (0 vs 44); GLM-4 stays toggle-only. Don't regress this to "GLM only has a switch". Preset ids map to models.dev ids via `PRESET_CATALOG_IDS`; unmapped providers fall back to a whole-catalog model-id match preferring reasoning-rich entries. Writes go through `saveProviderEntry`/`deleteProviderEntry` (save.ts) — merge-by-key, `undefined` values skipped, because the GUI only ever sends the keys the user actually edited (its config copy is redacted; echoing it back wholesale would blank real keys). Session exposes them as `saveProvider(id, patch)` / `deleteProvider(id)` (bootstrap validates the patch through `providerConfigSchema` to strip unknown wire keys; deleting the *active* provider is refused; editing the active one re-resolves best-effort via an empty `switch`), served as instant RPCs in serve.ts (the post-dispatch `pushState` broadcasts the updated redacted config) and mirrored on `RemoteSession` with the same `isTrustedTransport` guard as `switch` when the patch carries an `apiKey`. Zod schemas in `schema.ts`; provider presets (baseURL, key env vars, default models) in `providers.ts`; web-search backend presets (GLM standalone search endpoint / Exa / custom) in `search.ts` — `resolveSearchBackend` returns `undefined` on a missing key (never `MissingKeyError`, which would trigger the auth wizard) so `web_search` degrades to "not registered". **zod 4 layer trap**: `.partial()` does NOT strip `.default()` — a layer file's *missing* keys come back filled with phantom defaults (`provider:'deepseek'`, `language:'auto'`, …), and since layers merge by priority, a project layer's mere *existence* (e.g. `/approvals` persisted one) silently reset every global-layer default-carrier on every startup (the "switched model reverts after restart" bug). Two defenses, both load-bearing: `partialConfigSchema` is hand-written all-optional (new defaulted fields in `configSchema` MUST be mirrored there), and `readLayer` filters parsed output down to the keys actually written in the file.
- `src/permissions/` — four layers: `sandbox.ts` (realpath-based workspace containment, denies `.git/`, `.env*`, key/SSH material regardless of mode), `bash-rules.ts` (command judgment + `Bash(prefix:*)` rule matching, hard-denies `rm -rf`/`sudo`/`curl|sh`/force-push etc.), `net-rules.ts` (domain rules `WebSearch` / `WebFetch(domain:x)` via anchored glob match — never bash-style prefix match, which would let `example.com.evil.net` pass — plus a private/link-local/metadata hard-deny that even danger-full-access does not bypass), `gate.ts` (two orthogonal axes `sandbox` × `approval` plus a `plan` flag that overrides both; the old single-axis `readonly`/`ask`/`acceptEdits`/`yolo` survives only in `fromLegacyMode`; session vs. persisted allow rules in three buckets: allowBash / allowWrite / allowNet).
- `src/tools/` — builtin tools: `read write edit glob grep bash web_fetch todo` plus `web_search` when a search backend resolves, plus `task` (subagent: reuses the `Agent` class on a private EventBus so its per-step events stay out of the main timeline; only aggregated `task-progress` events reach the main bus; shares the PermissionGate but gets its own `readFiles` set; its toolset excludes `task`/`todo`/`exit_plan` — one level of recursion only, and `mode: 'explore'` narrows it to read-only tools; step cap is `taskMaxSteps` (falls back to `maxSteps`); its final assistant text is the tool result — truncated, and flagged `incomplete` on step-budget/length/error endings; tokens folded into the session total via `Agent.addExternalTokens`; the full inner transcript is persisted as a `kind: 'task'` record in the session JSONL via `store.saveTask` for post-hoc debugging, readable with `SessionStore.readTasks`). `summarizeToolResult` produces the localized one-line UI summary; tool *results* fed back to the model stay English. Web backend adapters live in `web-backends.ts`; both web tools funnel through `gate.checkNet` (per-domain confirm + remember).
- `src/lsp/` — LSP diagnostics feedback: `write`/`edit` call `LspManager.check()` after a successful write and attach errors/warnings (English, `diagnostics` field) to the tool result. Servers (typescript-language-server / pyright / gopls / rust-analyzer + user-configured) are spawned lazily per language, matched by extension; a server that fails to spawn is remembered as dead for the session. Everything degrades silently to `undefined` — diagnostics must never break the write itself. An empty first diagnostics batch gets a per-server grace window (`emptyGraceMs`, config `graceMs`; rust-analyzer/gopls publish empty-then-real) before being trusted; publishes for *other previously-checked files* arriving during a check surface as `otherFiles` lines (edit A broke B). Config lives under `lsp` (`enabled` / `timeoutMs` / `servers`), with a bare-optional layer schema and per-server-id deep merge in `mergeLayers` (same pitfall as `search`: `.partial()` does not strip inner defaults). Doctor's LSP section does a real initialize handshake for found-on-PATH servers (spawn → init → kill; TUI passes `session.lsp.statuses()` to skip re-spawning).
- `src/agent/` — the streamText loop, system prompt assembly (`prompt.ts` injects `AGENTS.md`/`MOJOCODE.md` from the project root), context compaction (`compact.ts`). Mid-turn guidance messages are queued and injected at step boundaries. `init.ts`/`review.ts` hold the canned-prompt commands (`/init`, `/review`): review collects its git summary server-side (execa, `reject: false`) and embeds **only scope summaries plus safe-prefix commands** — `git merge-base` is not in bash-rules' SAFE_PREFIXES, so the server resolves the SHA itself and the model never needs a prompting command; the full diff is never embedded (it would bloat the persisted history and tool output already truncates at 20k). The review prompt is dispatched through `wrapSkillPrompt`, so replay/rewind show `/review <scope>` with zero replay.ts changes; failures return as reason codes (`ReviewFailure`) which the UI maps to localized notices — git-error carries only the first stderr line (truncated) as `{message}`, never the full blob. `simplify.ts` is `/simplify`, the two-phase cleanup command: four read-only **explore** subagents run in parallel (one per axis — reuse / simplification / efficiency / abstraction), each with its own context and step budget via `runTaskSubagent`; the main conversation then runs one apply turn that merges the reports, verifies against the working tree and applies fixes uncommitted. `runAxisReviews` holds the phase-1 choreography with the subagent channel deps-injected (bootstrap passes `runTaskSubagent`) and emits **synthetic `task` tool-start/tool-end per axis** — `task-progress` only renders on an in-flight task row (`App`'s `activeTools`), and a canned launch makes no real tool call, so without the synthetic events phase 1 is minutes of silence. Axis prompts are honest about explore having **no shell**: the scope block's git commands belong to the apply turn; the subagents work from the summary plus reading files. The whole launch window (git collection + phase 1, during which the *main* agent is idle and `isRunning` is false) is guarded by `cannedLaunchPending` on both input paths — esc is ignored, plain messages in `handleSubmit` are rejected: there is no running turn to inject into, and letting one start would make the apply prompt hit the loop's re-entrancy guard and land in the user's turn as a guidance message. Failed axes keep their section ("NOT covered") and an all-fail still runs the apply turn; `/resume` does not replay the phase-1 synthetic rows (they are bus events, not history).
- `src/mcp/` — MCP client + bridge that wraps MCP tools as AI SDK tools, routed through the same PermissionGate.
- `src/i18n/` — `en.ts` / `zh-CN.ts` catalogs; a parity test asserts the two key sets match. Resolution: config `language` → `MOJOCODE_LANG` → `LC_ALL`/`LANG`. **UI strings are localized; text fed to the model (tool errors, denial reasons) is intentionally English-only** — mixed language degrades function calling.
- `src/ui/` — **SolidJS** (`@opentui/solid` 0.5.1, exact-pinned with `@opentui/core`, `solid-js` and `web-tree-sitter` — the same stack opencode ships) components in alternate-screen fullscreen mode. `kit.tsx` is the renderer adapter: Ink-shaped `Box`/`Text`/`useInput`/`useApp`/`render` over OpenTUI — components import kit, never `@opentui/*` directly (upstream 0.x breakage lands in one file). Kit absorbs the semantic gaps: OpenTUI `<text>` does not parse ANSI (kit's `Text` routes ESC-containing strings through `ansi-spans.ts` → `<span>`s; SGR 39/49 mean "inherit outer", which Diff's background highlight relies on); nested `<Text>` must be `<span>` (context-switched — and children resolution must happen INSIDE the provider, Solid's `children()` helper is eager); **span (TextNode) styles only apply via the `style` prop** (`style={{fg,bg,bold…}}`) — direct `fg=`/`bg=` attrs are silently ignored by the upstream reconciler, and the failure mode is text silently rendering in default white; plain printable keypresses in one synchronous burst are still merged into a single `input` dispatch (collapses N renders; the React-era flushSync/stale-closure machinery is gone — Solid handlers read signals live). Mouse is on (OpenTUI's `useMouse` defaults to true — that's what makes wheel-scroll and `useSelectionCopy`'s drag-select work), and kit exposes it as one prop: `onClick` on `Text`/`Box`, wired to `onMouseDown`/`onMouseUp` via `clickHandlers`. Four rules there, all load-bearing: a click is **down and up on the exact same cell** — anything looser (same row, same element) turns a horizontal drag-to-copy into a click, i.e. a mis-click that approves a permission prompt; the pending down-cell lives in a **per-renderer** `PointerState` (WeakMap), never per-element — an element that is pressed and then dragged away from never receives its own `up`, so per-element coordinates stay armed forever and the *next* drag that merely ends on that cell fires its `onClick` (verified repro: drag row1→row2, then drag elsewhere→row1, and row1's option decides); a click is also refused when the element **mounted after the previous click and within `CLICK_SETTLE_MS` (250ms)** — clicking a row usually swaps what occupies those same cells, so a double-click's second press lands on the freshly revealed row and applies it (double-clicking `/setting` → Language silently switched the locale to whatever row landed there). That window is per-renderer too, or tests leak it into each other's first click; UI tests that click twice in sequence must sleep past it. And `onClick` on a *nested* `<Text>` is dead, since those render as `<span>`/TextNode, which is not a Renderable and never enters the hit grid — it goes on the row's outermost `Text`, which a column container stretches to full width, so the whole row (trailing blank space included) is the hit area with no extra wrapper Box. List panels (`PermissionPrompt`, `SettingsPanel`, `RewindPicker`, `SessionPicker`, `ModePicker`) route click through the same action as the key binding, never a separate path; `Footer`'s mode segment opens `ModePicker` (the 3rd overlay in App's bottom-of-screen `Switch`), which lists all four presets plus `plan` and lands on App's `applyMode` — the same mutation `shift+tab`'s `cycleMode` performs, only with the landing spot named instead of blind-stepped. `cycleMode` walks `nextCycleStep`, which now covers **every** preset in `APPROVAL_PRESETS` order (read-only → ask → auto → full-access → plan → read-only); a free-form combination still falls to `plan` (it can't write anything, so a mis-press only tightens). `applyMode` takes an explicit `{ persist }` — no default, so every new entry point has to decide — and when set writes the preset to the **workspace** `.mojocode/config.json` through `persistPermissions`, the same path `/approvals` takes, never the global config, because loosening is a trust statement about one workspace; the write is fire-and-forget (a failure only pushes a warn notice — the session-level switch already took effect) and success pushes `notice.modeSavedTo`, since a click that rewrites a committable file must not be silent. Only the **named** paths persist — the mode picker and `/approvals`. `shift+tab` does **not**: it is a blind step whose landing spot you don't know before pressing, so a mis-press must not rewrite a project config, and the plan→read-only step is the sharp case — the ring has to land somewhere on the way out of plan mode, that landing is a consequence of *leaving plan*, not a statement about presets, and persisting it silently turned a checked-in `auto` into `read-only` after two taps. `plan` is never persisted on any path: it's a collaboration state, not a preset, and storing it would open every new session in plan mode. `full-access` is one keystroke away, so every path into it pushes the `notice.modeDanger` warning — a 2-second footer flash is not a record, and the transcript has to show which stretch ran without a sandbox. Nothing else gates on the danger flag: `savePermissions`, `snapshotState` (session JSONL) and `resumeOverrides` all treat full-access like any other preset (`isDangerousPermissions` is only a warning predicate now); the one combination still withheld from the session record is `permsPromoted` (read-only+never promoted to ask by approving a plan — that's this-approval-only, not a user's choice). Clicking a mode is safe by construction while a permission prompt is up: Footer is unmounted whenever `overlayOpen()`; the reverse direction is not automatic, so a permission request routes through `showPermission`, which closes **all three** lower-priority overlays (mode picker, settings panel, rewind picker) — the prompt outranks them in the `Switch`, but their signals survive the preemption and they resurrect over the Input once the user decides, where a reflexive enter hits *their* confirm action instead of submitting (worst case: the rewind picker truncates history). Closing them is exactly esc — all three hold only cursor/draft state; clicking must never do more than the keyboard can (`/setting`'s status-bar section is multi-select, so a row click toggles the draft and only enter commits). Keyboard stays the only guaranteed input (SSH, mouse-less terminals) — click is strictly additive. Kit's other mouse prop is `onScroll` (Box only): one cursor step per wheel event, deliberately ignoring `ScrollInfo.delta` (terminals send an event per notch; scaling by delta makes a list fly past), and it `stopPropagation`s so wheeling a menu never also scrolls the timeline underneath. Input's three lists (`/` command menu, `@` file menu, the enum-arg selector) already windowed at 8 rows with more-above/below hints — wheel and ↑/↓ go through the *same* `moveMenu`/`moveFileMenu`/`moveSelector` movers so wrap-around is identical; a wheel that clamped while the arrow key wrapped would be two feels for one list. The *timeline* does not use upstream's wheel handling at all: `attachSmoothScroll` overrides the scrollbox's `onMouseEvent` (per-instance, same trick as `handleKeyPress` above) so a notch only moves a **target** position, and a frame callback eases the real `scrollTop` toward it. Two upstream facts force this. First, `ScrollInfo.delta` is hardcoded to 1 by the mouse parser and the default `LinearScrollAccel` returns a flat multiplier of 1, so one notch = one line — dozens of flicks to get back a few screens (`scrollAcceleration` is upstream's only knob, and `MacOSScrollAccel` is not a fix: its base is still 1, so it addresses "scrolling for a long time", not "one notch does too little"). Second, upstream applies the step *instantly*, so any step bigger than a line is a visible jump — raising the step alone buys speed at the cost of smoothness (this is exactly what opencode's default 3-lines-per-notch feels like, and why it still reads as steppy). So `StreakScrollAccel` sets the target (3 lines/notch, +1 per notch within an 80ms streak, capped at 8) and the easing (`1 - e^(-dt/55ms)`, floor of one line per frame — the terminal's minimum unit; a proportional tail would otherwise grind at sub-line speed forever) spends it over several frames. `requestLive()` runs only while the animation does (`dropLive()` on landing), so the renderer is back to on-demand at rest — and `targetFps: 60` in `render()` exists **for this animation only**: it is the frame rate of a live loop, while on-demand renders are already capped by `maxFps` 60. Ordering matters at rest: sticky-follow moves `scrollTop` behind our back, so a frame that sees a value it did not write abandons the animation and re-syncs, and a notch arriving while idle re-seeds position/target/written from the box (all three — seeding only two makes the very first frame after a sticky jump look external and swallow the gesture). Page/Home/End stay upstream's instant behavior, but stop the easing first or the two fight over `scrollTop`. A menu is still exactly one row per notch, instantly — a list you pick from has no "fast" mode and no animation. `tests/support/otui.tsx` exposes `click(x, y)` and `scroll(x, y, dir)` over the upstream `createMockMouse`. Solid discipline: never destructure props; derived values are functions/memos; multi-signal updates that an effect observes must be `batch()`ed (the pasted-image pruning effect bug). Switching the language (`/setting` → Language) re-evaluates static strings by keyed-remounting the JSX body while all signals live outside it — the `<Show when={locale()} keyed>` child callback **must declare a parameter**: Solid's `Show` gates the by-value call on `children.length > 0`, so a zero-arity arrow is returned as a plain reactive child, the memo keeps handing back the same function reference, and nothing rebuilds (the language flips but every static string stays in the old locale). `SettingsPanel.tsx` is the `/setting` panel — a two-level modal (section list → per-section editor: language single-select, status bar multi-select over a draft set so esc discards) rendered in the same mutually-exclusive branch as `PermissionPrompt`/`RewindPicker`/`ModePicker`, i.e. Input is unmounted and its own `useInput` owns the keyboard. New user-facing settings go in there, not into new slash commands (`/lang` and `/statusbar` were folded into it). Timeline is a `<scrollbox stickyStart="bottom">` (`ScrollArea` — the flexGrow/flexShrink/flexBasis:0/minHeight:0 quartet is load-bearing); items are immutable so `<For>` reuses entries with zero re-render (React.memo's job, now free), `renderMarkdownAnsi` stays LRU-cached by `(item.key, width)` in `md-cache.ts`. `/focus` (`focus.ts` `collapseItems`) filters the timeline at render time — `user`/`assistant`/`error`/`banner` and ALL notices are NEVER hidden (iron law, locked by `tests/focus.test.ts`). Every turn ends with a `kind: 'turn'` line (model · elapsed · that turn's tokens, from the cumulative delta measured at `turn-start`); aborted/error turns have their own line and don't get one. Single-line info rows must be measured and cut before layout — an overflowing OpenTUI flex row shrinks its children and silently eats the spaces around separators, so `Footer.fitParts` narrows cwd first, then gives it its own row, then drops segments by priority. Footer is a two-group status bar — left (mode chip / model / cwd / think), right (context meter / total) — and the gap between the groups is an explicitly computed run of spaces, **not** `justifyContent`: flex's space-between shrinks children on overflow, i.e. the exact failure fitParts exists to prevent, so "never overflows" stays the job of one function. Overflow never promotes the right group to its own row (segments get dropped instead) — every extra footer row costs the timeline one. The mode renders as an inverse chip (`modeChipColors`, explicit fg **and** bg like the diff palette, red for full-access) followed by a single space rather than ` · `: the chip's own edge already reads as a separator. ## Gotchas (documented in README, do not regress)

- GLM's baseURL is `/api/paas/v4` — never append `/v1` (404s).
- Never hardcode model IDs; presets are only starting defaults, `mojocode models` fetches the live list.
- Use `result.responseMessages` for history, not `result.response.messages` — the latter only contains the last step and silently drops earlier tool calls.
- Kit's `render()` defaults `exitOnCtrlC: false` — the renderer would otherwise destroy itself before `useInput` sees ctrl+c, breaking the double-ctrl+c-to-exit logic (startup wizard/picker opt back in).
- Cross-compiling needs the target's `@opentui/core-<platform>` package on disk; `build-binaries.ts` installs missing ones on demand (`npm install --no-save --force`). Do NOT pin them in package.json — each declares os/cpu, so a bare `npm ci` would EBADPLATFORM on every machine. The script also pins `process.env.OPENTUI_LIBC` per Linux target via define — without it both glibc and musl native libs get embedded (+~18MB).
- Readonly enforcement uses `gate.assertCanMutate()` *before* tools do any work, separate from `checkWrite`, because tools short-circuit (e.g. `write` returns early on unchanged content) and the guarantee must not depend on which branch ran.
- In-turn compaction only shrinks the messages sent to the model; the persistent history stays long, and the `historyNeedsCompact` flag forces compaction at the next turn start (otherwise the shrunken `lastInputTokens` masks the need). The same flag also covers the *other* blind spot: `setHistory` (resume, rewind) invalidates `lastInputTokens`, and `shouldCompact(undefined, …)` is `false`, so the swapped-in history would go out verbatim. Since **resume no longer switches back to the session's recorded provider/model** (it keeps whatever the current config resolves — `resumeOverrides` only restores permissions now), a long history can land on a smaller window and 400 on the first turn, identically on every retry. `setHistory` therefore seeds the flag from `estimateTokens` (CJK ≈ 1 token, else ¼, images stripped) — a local estimate used **only to trigger** compaction, never to conclude none is needed: under-estimating falls back to the old behavior, over-estimating costs one extra summary. `meta.provider`/`meta.model` are now display-only (session picker, `mojocode sessions`) and are kept current via `store.setModel` on switch/resume.
- `src/config/paths.ts` resolves the home dir from `$HOME`/`$USERPROFILE` first, **never bare `os.homedir()`** — Bun snapshots the home dir at startup and ignores later `process.env.HOME` mutations, so the single binary would put `~/.mojocode` somewhere else than the Node build whenever HOME is set explicitly (containers/CI), and tests that mock HOME silently read the developer's real config instead.
- Node floor is **22**, not 20: execa 10 calls `Set.prototype.union` (ES2024) at import time, so Node 20 dies before `--version` prints. `engines`, the CI matrix and the README all say 22 — keep them in sync if a dependency raises the floor again.
- `vitest.config.ts` (core lane) carries the same `zod` → `index.cjs` and `solid-js` → `dist/solid.js` aliases as the UI config: CI also runs the core suite under Bun (`bun --bun x vitest run`) to guard dual-runtime compat, and without the aliases `import { z }` is undefined there.
